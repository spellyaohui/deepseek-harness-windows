# AgentTeams Profile 就绪诊断与动态任务规划

用户已确认采用：固定 Profile 的成员、Provider/model/思考策略，由队长根据当前目标动态规划任务；回归后生成本地测试安装包，测试通过再发布。

## 已核实的原因

- 当前用户默认 Profile 已绑定为 `software-delivery`，不是未保存默认团队。
- 用户有效设置把该 Profile 设为 `taskPlanning: seed`，成员 4 个，但固定任务为 0 个。严格创建边界会拒绝该配置。
- 最新会话没有真正调用创建或启动工具，只有无团队的状态查询；已有防空转暂停工作正常。
- 桌面默认层本来是 `captain`，但不能覆盖用户的正式设置。改默认层或自动添加模板任务都不能正确解决问题。

## 约定的修复

1. 无团队时，按可信的已保存默认 Profile 给出具体诊断：未绑定、绑定不存在/配置无效、固定模板零任务、已就绪的动态/固定模板。明确区分“已保存默认”与本轮用户命令；当前直接用户选择仍优先，不能被默认诊断误判。
2. 就绪提示明确要求调用 `agent_teams_create`；动态规划还要求创建任务并分配给冻结角色，不能把空团队当作工作已启动。
3. 固定模板零任务给出两条准确的人工修复路径：添加真实模板任务，或切换成队长动态规划。此用户选择后一条。
4. 用户在 2026-10-14 确认“先只修代码和打包，配置我自己切换”：本轮不改任何用户配置。交付时说明在正式 Profile 编辑器把 `software-delivery` 切换为“队长动态规划”并保存；保留成员、模型/思考策略、任务数据、提示词、默认绑定和临时策略。不得通过恢复默认、直接改 YAML 或安装时迁移来替用户切换。
5. 既有三次空查暂停保留，暂停信息也有可执行的诊断；不自动创建团队、不自动选择 Profile、不自动派遣、不复用旧 Team，不放开临时/Native 边界。

## 契约与验收

- 不新增工具、设置项、依赖或模型路由；状态成功值仍为 `{active:false}`，活动团队输出不变。
- 当前用户命令优先于默认绑定；诊断不授予权限。读取和诊断无 Team/设置/子会话写入。
- 保留严格 V2、质量门、角色继承、唯一 durable gateway、CAS、Home/CLI 拒绝、Superpowers。
- 内置完整队长提示仍不超过 3,500 字符。无旧配置迁移层。
- 新版本为 AgentTeams `0.1.23-desktop.5`、wrapper `0.2.0-rc.23`；宿主仍固定 `0.2.0-rc.2`，上游来源不变。
- 真实工具/AgentLoop 测试证明：精确诊断、空 seed 创建零写入拒绝、captain 创建后任务实际投递到冻结角色而非临时模型。模型外部请求用离线适配器代替，其余运行时使用真实组件。
- 完整离线 `npm run verify:upstream` 通过后打包，核对实际安装依赖、unpacked/ZIP 闭包、图标、版本、EXE/ZIP/blockmap 大小及 SHA-256、签名。
- 仅本地测试包，不安装、不重启在用客户端、不提交/push/tag/Release；保留所有原有用户文件和之前的安装包。
