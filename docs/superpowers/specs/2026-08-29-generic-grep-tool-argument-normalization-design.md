# 通用 grep 工具参数归一化设计

## 背景

部分通过 OpenAI 兼容接口接入的模型能够看到正确的 `grep` 工具 Schema，
但仍可能返回以下参数：

```json
{
  "description": "pattern: 请稍后重试",
  "path": "frontend/src"
}
```

`grep` 的真实必填字段是 `pattern`，因此 Harness 的严格工具参数校验会正确
拒绝该调用，并报告 `missing required property "pattern"`。已经观察到
`woyaopro/gemini-3.7-flash-high` 产生这种输出，但错误形态属于模型工具调用
协议兼容问题，不应绑定到某个供应商或模型 ID；更换供应商后，相同模型或其他
模型仍可能产生同样的结构。

## 决策

Windows wrapper 在 `dsh-llm-pi-ai` 把最终 pi-ai 工具调用转换为 Harness
持久化 assistant block、并交给 Agent Loop 之前，执行一条跨供应商、跨模型的
确定性参数别名归一化规则。

只有同时满足以下条件才允许转换：

1. 工具名严格等于 `grep`；
2. 参数是非 `null`、非数组的普通 JSON 对象；
3. 参数对象没有自己的 `pattern` 字段；
4. `description` 是字符串；
5. `description` 整体严格匹配单行 `pattern: <非空搜索内容>`，只允许冒号两侧
   存在空格或制表符。

满足条件时：

- 将冒号后的非空内容写入 `pattern`；
- 删除错误的 `description`；
- 原样保留 `path`、`include` 和其他字段；
- 不修改原参数对象。

任何一个条件不满足时都返回原参数对象，继续由上游严格 Schema 校验决定是否
失败。已有 `pattern` 永远不会被覆盖，即使同时存在看似可转换的 `description`。

## 所有权与边界

- 该行为属于 Windows wrapper 的第三方模型工具兼容层，不属于文件搜索插件；
  `grep` 的 Schema 和必填字段保持不变。
- 归一化发生在 `@deepseek-ai/dsh-llm-pi-ai` 的最终 `toolcall_end` 边界，确保
  Harness 持久化消息、Agent Loop 和工具执行看到同一份最终参数。
- 不直接修改 `node_modules`。wrapper 通过既有 ESM loader 和
  `win-hide-console-rewrite.js` 重写已安装的官方模块。
- 实现应采用可扩展的“已知、无歧义工具参数别名”边界；未来只有获得真实日志和
  回归样本后，才能新增其他工具规则。

## 为什么不增加模型级开关

图片输入的“自动 / 文本和图像 / 仅文本”描述模型能力，用户可能掌握目录无法获取
的事实，因此适合模型级手动覆盖。

本问题则是一个可由参数结构完全判定的协议瑕疵。增加“特殊处理”开关会让用户在
更换供应商或模型后重复配置，并产生容易过期、含义不明确的状态；关闭开关还会让
已知可安全修复的同一错误重新出现。因此本规则自动应用于所有供应商和模型，但只
接受上述无歧义形态。

## 被拒绝的替代方案

### 按供应商和模型 ID 限定

实现范围最窄，但同一错误换供应商后会复发，也会累积供应商名称和模型名称分支。
不采用。

### 每个模型增加工具兼容开关

能够人工控制，但增加设置 UI、持久化 Schema、运行时解析和维护成本，且用户通常
无法提前知道模型会以何种错误形态调用工具。不采用。

### 放宽 `grep.pattern` 必填约束

会允许真正缺少搜索内容的调用进入执行器，掩盖模型错误并改变上游工具契约。
禁止采用。

## 测试与验收

回归测试必须证明：

- 任意供应商和任意模型使用精确别名形态时都能得到 `pattern`；
- `path`、`include` 和未知字段被保留，输入对象不被修改；
- 已有合法 `pattern` 不被覆盖；
- 非 `grep` 工具、空搜索内容、多行内容、额外说明、非对象参数保持原样；
- 实际安装的 `dsh-llm-pi-ai` 源码能被重写，重写幂等且模块仍可导入；
- 原有严格工具 Schema、AgentTeams、CPA、OpenCode 和模型图片能力三态回归继续
  通过；
- `npm run verify:upstream` 在打包前完整通过。

## 非目标

- 本次不增加 Responses API 与 Chat Completions 的协议选择功能；
- 不基于模型名称猜测更多兼容行为；
- 不自动修复无法从结构唯一推导目标字段的参数；
- 不删除或弱化“自动 / 文本和图像 / 仅文本”的模型图片能力设置。
