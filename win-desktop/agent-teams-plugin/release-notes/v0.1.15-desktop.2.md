# v0.1.15-desktop.2

## Fixed

- Complete the staged Web Revision/CAS chain. Activity snapshots expose the
  current `planRevision`; member edits, task additions/updates/removals and Web
  approval submit that revision; the Host rejects stale writes and returns the
  committed revision.
- Bind Web approval to a one-time credential prepared and consumed for the same
  Team, Captain and plan revision. This removes the old placeholder call that
  raised `staged plan update requires revision-aware options`.
- Restore the upstream `v0.1.15` Alpha.2 Connection authentication and
  Host/Origin checks for raw AgentTeams state, plan, halt, artwork and local
  model-catalog routes. Missing authentication, hostile origins and an
  unavailable Connection fail closed before handlers run.

## Changed

- Ordinary delegation now explicitly defaults to `approval="automatic"`.
  The Captain omits the optional Team name, lets AgentTeams generate it, and
  creates captain-planned task names/contracts itself. Staged review remains
  available only when the user explicitly asks to inspect the plan before
  startup.
- Keep the complete built-in `software-delivery` guidance below the existing
  3,500-character budget.

No historical Team/Profile migration layer is added, and AUTO remains absent.

# v0.1.15-desktop.2（Windows fork）

## 修复

- 打通 staged Web 的 Revision/CAS 全链路：活动快照提供当前
  `planRevision`，成员编辑、任务新增/保存/删除和 Web 审批都携带该
  revision；Host 拒绝过期写入并返回已提交 revision。
- Web 审批按同一 Team、队长和计划 revision 准备并消费一次性凭据，移除
  会触发 `staged plan update requires revision-aware options` 的旧占位调用。
- 恢复上游 `v0.1.15` 针对 Alpha.2 的 Connection 认证和 Host/Origin
  检查；未认证、恶意跨站来源或 Connection 未就绪时均在进入处理器前
  fail closed。

## 调整

- 普通委派明确默认 `approval="automatic"`：队长省略可选 Team 名称，由
  AgentTeams 自动生成，并自行创建 captain-planned 任务名称与契约。只有
  用户明确要求启动前审计划时才使用 staged 审核。
- 完整 `software-delivery` 系统提示继续保持在 3,500 字符预算内。

不增加旧 Team/Profile 迁移层，AUTO 仍保持移除。
