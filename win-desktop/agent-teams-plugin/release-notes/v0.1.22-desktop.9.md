# v0.1.22-desktop.9

2026-10-06。根据导出团队会话（主会话与 11 个成员会话）复核出的问题修复任务归属、
验收证据和交付门禁；上游 v0.1.22 与 Harness 0.2.0-rc.2 固定版本不变。

- 队长接管的任务跨回合保留：队长回合结束不再作废 attempt、退回共享池或转给其他成员。
- 验收结果和验证命令按合同条目逐条匹配（只容忍全角/空白/句尾标点差异），条数相同的无关条目不再通过；被拒时列出缺失条目。
- implementation/repair 完成时用 Git 工作树快照核对 changedPaths：不能用目录代替文件，范围内改动必须上报，范围外改动即使从清单删掉也会被拒绝。非 Git 工作区只跳过实际改动核对。
- 编号成员（如 implementer-2）继承基础角色的执行提示词，自带提示词时以自带为准。
- `agent_teams_amend_task` 遇到合同外字段（如 `dependencies`）整体拒绝、零写入，不再部分成功。
- integration（合并/发布/部署）任务在团队全部审查通过前不能派发、认领或接管，事后创建的最终审查同样生效。
- 成员回合因输出上限（max-tokens）截断时，向队长报告具体原因，不再显示成普通“空闲未交结果”。
- 其中队长 idle 退回、按条数兜底和 amend 静默丢字段来自上游 v0.1.22，不提交上游 PR；后续刷新上游时作为首要对照点：上游仍存在则重新应用本地修复，上游已改动则重新分类并保留回归。
- 测试数据中的 provider 名改为中性的 `alt-gateway`；完整离线 verify:upstream 通过，无实际模型请求或状态迁移。
